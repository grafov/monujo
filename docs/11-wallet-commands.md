# 11. Команды `wallet`

Группа `wallet` управляет локальным **зашифрованным хранилищем
ключей** (keystore): создаёт новые кошельки, импортирует существующие
ключи, показывает локальный список, проверяет пару «адрес в файле —
парольная фраза». **Сетевых вызовов эти команды не
делают** — поэтому одинаково применимы и на онлайн-ПК, и на
air-gap-машине. Те же файлы потом используются командами `monujo hot`
(онлайн-операции) и `monujo offline sign` (подпись на изолированной
машине).

```text
monujo wallet
├── list          — показать локальные кошельки
├── create        — создать новый кошелёк (случайный ключ)
├── import        — импортировать существующий ключ (hex)
└── check         — проверить, что парольная фраза открывает кошелёк (без сети)
```

Глобальные ключи (`--network`, `--output`, `--keystore-dir` и т. д.)
применимы ко всем подкомандам. Подробнее см.
[03 — Конфигурация](03-configuration.md).

## Общие принципы

- **Парольная фраза**. `wallet create` и `wallet import` запрашивают
  парольную фразу через TTY без эха — два раза подряд для
  подтверждения. Альтернатива — флаг `--generate-passphrase`, который
  сгенерирует случайную фразу и напечатает её один раз в stderr (см.
  [06 — Хранилище ключей → «Генератор парольных фраз»](06-keystore.md#генератор-парольных-фраз)).
- **Стирание секретов**. Парольная фраза и материал приватного ключа
  затираются нулями (`ZeroPassphrase`, `Wipe`) сразу после
  использования.
- **Запись метаданных**. При создании/импорте текущий `--network`
  записывается в массив `networks` метаданных файла. Эта запись
  позже используется командами `hot` для проверки сетевой
  непротиворечивости.
- **Имя кошелька** (`--name`) санитизируется: разрешены только
  `a-z`, `A-Z`, `0-9`, `-` и `_`. Прочие символы заменяются на `_`.
  Пустое имя превращается в `default` (так что `--name " "` создаст
  файл `default.json`).
- **`--from` в `wallet check`**. Значение трактуется так же, как в
  командах `hot` и `offline`: строка, похожая на Tron base58-адрес,
  ищется среди локальных кошельков по полю `address` в JSON; иначе
  строка считается **именем** кошелька. Для проверки нужен файл в
  keystore (произвольный чужой адрес без локального файла не
  проверяется).

## `wallet list`

Показывает локально сохранённые кошельки: имя, адрес, перечень сетей
из метаданных. **Расшифровывание не выполняется**, парольная фраза
не нужна.

### Использование

```bash
monujo wallet list
monujo --output json wallet list
```

### Флаги

Локальных флагов нет. Локально считывается каталог
`--keystore-dir`/`MONUJO_KEYSTORE_DIR`/`~/.config/monujo/keystore`.

### Что происходит

1. Открывается каталог keystore. Если его нет, выводится пустой
   список (без ошибки).
2. Перебираются все `*.json` (подкаталоги пропускаются).
3. Каждый файл парсится как `EncryptedWalletFile`. Файлы с другой
   версией формата или без поля `address` тихо пропускаются.
4. Записи сортируются по имени.

### Пример: формат `table`

```text
$ monujo wallet list
Keystore: /home/user/.config/monujo/keystore
NAME    ADDRESS               NETWORKS
funding TFG7NgT...            mainnet,shasta
imported TXYZ...              -
myhot   TLcVUPa...            shasta
```

Колонки разделены табуляцией. Если в `networks` пусто — печатается `-`.
Если каталог пуст — `No wallets.`.

### Пример: формат `json`

```json
{
  "keystore_dir": "/home/user/.config/monujo/keystore",
  "wallets": [
    {"name": "funding", "address": "TFG7NgT...", "networks": ["mainnet", "shasta"]},
    {"name": "imported", "address": "TXYZ..."},
    {"name": "myhot", "address": "TLcVUPa...", "networks": ["shasta"]}
  ]
}
```

`networks` пропускается из JSON, если пусто (тег `omitempty`).

## `wallet create`

Создаёт **новый** кошелёк: генерирует случайный secp256k1 ключ,
выводит из парольной фразы Argon2id-ключ, шифрует приватный ключ
AES‑256‑GCM, записывает файл с правами `0600`. Текущий `--network`
автоматически попадает в метаданные `networks` нового файла.

### Использование

```bash
monujo wallet create --name <ИМЯ> [--export-private-key]
monujo --network shasta wallet create --name testhot
monujo --output json wallet create --name myhot --export-private-key
```

### Флаги

| Флаг | Тип | Обязательный | По умолчанию | Описание |
|------|-----|--------------|--------------|----------|
| `--name` | string | да | — | Имя кошелька. Превратится в файл `<safeName>.json` в `--keystore-dir`. |
| `--export-private-key` | bool | нет | `false` | Печатать сгенерированный приватный ключ один раз. **Опасно**: ключ окажется в выводе терминала или JSON‑потоке. |
| `--overwrite` | bool | нет | `false` | **ОПАСНО**: разрешить замену уже существующего файла кошелька. Старый приватный ключ будет безвозвратно потерян. На TTY дополнительно запрашивается `[y/N]`; без TTY выполняется без доп. подтверждения. |
| `--generate-passphrase` | bool | нет | `false` | Сгенерировать случайную парольную фразу и напечатать её один раз вместо интерактивного ввода. |
| `--generate-words` | int | нет | `7` | Количество слов в сгенерированной фразе (≥ 4). |
| `--generate-dict` | string | нет | `english` | Словарь: `english`, `english-short`, `esperanto-x`, `esperanto`, `russian`. |
| `--generate-separator` | string | нет | ` ` | Разделитель между словами. |
| `--generate-capitalize` | bool | нет | `false` | Делать первую букву каждого слова заглавной. |
| `--generate-digits` | int | нет | `0` | Дописать N случайных десятичных цифр в конец фразы. |
| `--generate-allow-non-tty` | bool | нет | `false` | Разрешить вывод сгенерированной фразы в не-TTY stderr (**небезопасно**). |

### Что происходит

1. Запрашивается новая парольная фраза дважды (или генерируется при
   `--generate-passphrase`). При несовпадении — ошибка
   `passphrases do not match`.
2. Генерация ключа: `crypto.GenerateKey()` из go‑ethereum.
3. Из публичного ключа вычисляется Tron‑адрес.
4. Шифрование: `argon2id(passphrase, random_salt)` →
   `AES-256-GCM(nonce=random_12, plaintext=raw_priv_32)`.
5. Файл `<keystore_dir>/<safeName>.json` создаётся с правами `0600`.
   Если каталога ещё нет, он создаётся с правами `0700`.

### Пример: формат `table`

```text
$ monujo wallet create --name myhot
New keystore passphrase: ********
Confirm passphrase: ********
Created wallet "myhot" -> TLcVUPa...
Keystore: /home/user/.config/monujo/keystore
```

С `--export-private-key`:

```text
$ monujo wallet create --name myhot --export-private-key
...
WARNING: printing private key is unsafe; anyone with this hex can spend funds.
Private key (hex): 7b8a...c9d0
```

### Пример: формат `json`

```json
{
  "name": "myhot",
  "address": "TLcVUPa...",
  "path": "/home/user/.config/monujo/keystore"
}
```

С `--export-private-key`:

```json
{
  "name": "myhot",
  "address": "TLcVUPa...",
  "path": "/home/user/.config/monujo/keystore",
  "private_key_hex": "7b8a...c9d0"
}
```

### Что важно знать

- Адрес, полученный из ключа, действителен в **обеих** сетях
  (mainnet и Shasta). Метка `--network` влияет только на то, какая
  сеть запишется в `networks` метаданных и какая будет использоваться
  по умолчанию для последующих команд.
- Файл создаётся через прямой `os.WriteFile` (не атомарно). Если
  процесс прерван между генерацией ключа и записью файла, ключ
  будет потерян, поскольку приватный ключ только что генерировался
  в памяти и не сохраняется нигде.
- Если файл с таким именем **уже существует**, команда по умолчанию
  завершается с ошибкой `wallet "<имя>" already exists at <путь>;
  use --overwrite to replace (DANGEROUS, irreversible)` ещё до
  запроса парольной фразы. Замена возможна только с явным
  `--overwrite`: на TTY дополнительно запрашивается `[y/N]`, в
  неинтерактивном режиме (скрипт, CI, перенаправленный stdin)
  перезапись выполняется без доп. подтверждения — сам флаг считается
  подтверждением. Потерянный таким образом приватный ключ **не
  восстановим**.

## `wallet import`

Импортирует существующий приватный ключ (64 hex‑символа) в новый файл
keystore. Текущий `--network` записывается в метаданные.

### Использование

```bash
monujo wallet import --name <ИМЯ> --key-hex <64_HEX>
# или
MONUJO_IMPORT_KEY=<64_HEX> monujo wallet import --name <ИМЯ>
monujo --network shasta wallet import --name testhot --key-hex 0x...
```

### Флаги

| Флаг          | Тип    | Обязательный | По умолчанию | Описание                                                                                                                                                           |
|---------------|--------|--------------|--------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--name`      | string | да           | —            | Имя файла keystore.                                                                                                                                                |
| `--key-hex`   | string | нет          | —            | 64 hex‑символа приватного ключа secp256k1. Опционально с префиксом `0x`.                                                                                           |
| `--overwrite` | bool   | нет          | `false`      | **ОПАСНО**: разрешить замену уже существующего файла кошелька. Старый приватный ключ будет безвозвратно потерян. На TTY — с подтверждением `[y/N]`; без TTY — без. |
| `--generate-passphrase` и связанные `--generate-*` | — | нет | — | Те же флаги генерации фразы, что у `wallet create`. |

Если `--key-hex` не задан, программа берёт ключ из переменной
`MONUJO_IMPORT_KEY`. При отсутствии и того, и другого — ошибка:

```
provide --key-hex or set MONUJO_IMPORT_KEY with the hex private key
```

### Что происходит

1. Парсится hex‑ключ: проверяется длина (ровно 64 символа) и
   корректность (валидный ECDSA secp256k1, не все нули).
2. Если файл с таким именем уже есть в keystore, команда
   отказывается продолжать без `--overwrite` (аналогично
   `wallet create`, см. соответствующий раздел выше).
3. Запрашивается пароль дважды (или генерируется через
   `--generate-passphrase`).
4. Шифруется и сохраняется так же, как в `wallet create`.
5. Адрес в файле — детерминированно из ключа.

### Пример: формат `table`

```text
$ monujo wallet import --name imported --key-hex 7b8a...c9d0
New keystore passphrase: ********
Confirm passphrase: ********
Imported wallet "imported" -> TXYZ...
Keystore: /home/user/.config/monujo/keystore
```

### Пример: формат `json`

```json
{
  "name": "imported",
  "address": "TXYZ...",
  "path": "/home/user/.config/monujo/keystore"
}
```

### Безопасность

- Ключ из переменной окружения может попасть в логи и историю
  shell. Используйте `MONUJO_IMPORT_KEY` только в контролируемом
  окружении (одноразовая запись, без записи в `.bash_history`).
- В режиме `table` сам ключ нигде не печатается; в режиме `json`
  тоже — `import` не имеет аналога `--export-private-key`.

## `wallet check`

Проверяет **офлайн** (без RPC и без отправки транзакций), что
введённая парольная фраза расшифровывает локальный файл кошелька и что
расшифрованный ключ даёт тот же Tron-адрес, что записан в поле
`address` этого файла. Удобно сверить бекап: не перепутаны ли имя
файла, адрес из записей и парольная фраза.

В отличие от `wallet list`, команда **выполняет полное дешифрование**
(ключ кратковременно существует в памяти, затем затирается). В отличие
от `hot balance`, она не обращается к сети.

Если файл ещё в формате v1 (scrypt), успешная проверка может
**запустить автоматическую миграцию** в v2 (argon2id), как и любая
другая операция с `LoadPrivateKey` — см.
[06 — Хранилище ключей → Миграция v1 → v2](06-keystore.md#миграция-v1--v2).

### Использование

```bash
monujo wallet check --from <ИМЯ_КОШЕЛЬКА>
monujo wallet check --from T...   # если адрес есть в wallet list
monujo --output json wallet check --from myhot
```

### Флаги

| Флаг     | Тип    | Обязательный | По умолчанию | Описание |
|----------|--------|--------------|--------------|----------|
| `--from` | string | да           | —            | Имя кошелька в keystore **или** его Tron base58-адрес (как в `hot` / `offline`). Адрес без соответствующего локального файла даёт ошибку. |

### Что происходит

1. По `--from` находится запись в локальном keystore (только чтение
   метаданных списка).
2. Один раз запрашивается парольная фраза (TTY без эха; в не-TTY
   можно передать фразу в stdin, завершающий перевод строки
   обрезается).
3. Выполняется `LoadPrivateKey`: KDF, AES-GCM, сверка производного
   адреса с полем `address` в JSON.
4. При успехе — короткое сообщение в stdout (или JSON с полями
   `ok`, `wallet`, `address` при `--output json`).

При неверной фразе или повреждённом файле команда завершится ошибкой
(например, `decryption failed (wrong passphrase or corrupt file)`).
