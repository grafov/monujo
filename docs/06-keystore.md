# 06. Хранилище ключей (keystore)

`monujo` хранит приватные ключи в локальном **зашифрованном
хранилище**. Каждый кошелёк — это отдельный JSON‑файл в каталоге,
заданном `--keystore-dir` / `MONUJO_KEYSTORE_DIR` / по умолчанию
`~/.config/monujo/keystore`.

## Расположение и права

- Каталог keystore создаётся автоматически (`os.MkdirAll(... 0o700)`)
  при первой записи (`hot create`/`hot import`).
- Файлы создаются с правами `0600` (`os.WriteFile(... 0o600)`).
- Имя файла строится из `--name` через функцию `safeName`:
  - разрешённые символы: `a-z A-Z 0-9 _ -`,
  - все прочие заменяются на `_`,
  - пустое имя превращается в `default`.
  Например, `--name "My Cold #1"` создаст файл `My_Cold__1.json`.
- При записи метаданных (см. ниже) используется атомарная замена через
  временный файл `.monujo-keystore-*.tmp` и `os.Rename`.
- Чтение ключа идёт через `os.OpenRoot(keystoreDir)`: открыть файл
  можно **только** внутри указанного каталога; попытка эскейпа через
  симлинк или `..` гарантированно провалится на уровне системного
  вызова, даже если в `safeName` появится дыра.

## Формат файла v1

Текущая версия формата — `1`. Программа не принимает другие версии и
выдаёт ошибку `unsupported keystore version <N>` при их обнаружении.

Пример минимального файла:

```json
{
  "version": 1,
  "address": "TLcVUPaYnQp...",
  "networks": ["mainnet"],
  "kdf": "scrypt",
  "salt_hex": "8a7b...e1f2",
  "n": 32768,
  "r": 8,
  "p": 1,
  "cipher": "aes-256-gcm",
  "nonce_hex": "5c1d...90ab",
  "data_hex": "fa12...34cd"
}
```

### Поля

| Поле          | Тип             | Описание                                                                                                                                                                   |
|---------------|-----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `version`     | int             | Всегда `1` для текущей версии.                                                                                                                                             |
| `address`     | string          | Tron‑адрес в Base58Check, выведенный из публичного ключа. Используется при `hot list`, и сверяется при дешифровании (если расшифрованный ключ даёт другой адрес — ошибка). |
| `networks`    | array of string | Опционально. Сети, на которых этот кошелёк уже использовался: `mainnet`, `shasta`. Уникальные, отсортированные. Может отсутствовать (`omitempty`).                         |
| `kdf`         | string          | Имя KDF. В текущей версии — всегда `"scrypt"`.                                                                                                                             |
| `salt_hex`    | string          | Случайная соль scrypt, 32 байта в hex.                                                                                                                                     |
| `n`, `r`, `p` | int             | Параметры scrypt: `N=32768`, `r=8`, `p=1`.                                                                                                                                 |
| `cipher`      | string          | Имя шифра: `"aes-256-gcm"`.                                                                                                                                                |
| `nonce_hex`   | string          | Случайный nonce GCM, 12 байт в hex.                                                                                                                                        |
| `data_hex`    | string          | Шифротекст приватного ключа (32 байта плэйнтекста + 16 байт GCM‑тэга), в hex.                                                                                              |

## Криптография

```
DK         = scrypt(passphrase, salt, N=32768, r=8, p=1, dkLen=32)
ciphertext = AES-256-GCM(key=DK, nonce=random_12, plaintext=raw_priv_key_32)
```

- **scrypt**: stdlib `golang.org/x/crypto/scrypt`. Параметры
  фиксированы в коде (`scryptN=32768, scryptR=8, scryptP=1`),
  длина выводимого ключа — 32 байта.
- **AES‑256‑GCM**: `crypto/aes` + `crypto/cipher.NewGCM`. Тэг
  аутентификации (16 байт) добавляется в конец `ciphertext`.
- **Источник случайности**: `crypto/rand.Reader` для соли и nonce.
  Стойкость соответствует ОС.
- **Стирание**: после дешифрования и подписания программа
  обнуляет:
  - `passphrase` (`ZeroPassphrase`);
  - выведенный scrypt‑ключ (`zeroBytes`);
  - буфер плэйнтекста приватного ключа (`zeroBytes`);
  - материал ECDSA‑ключа (`zeroPriv` обнуляет `D.Bits()`).
  Защита от утечек через swap/корки **не гарантируется** и зависит
  от ОС.

## Метаданные `networks`

Поле `networks` — это «дневник» использований кошелька, помогающий
не перепутать mainnet с тестовой сетью.

### Когда заполняется

- При `hot create --network <X>` и `hot import --network <X>` —
  записывается `[X]`.
- После успешной отправки `hot send-trx`/`hot send-usdt` с
  `--network <X>` — если `X` отсутствует, добавляется
  (`EnsureNetworkRecorded`). Шифр не пересоздаётся, меняются
  только метаданные, файл переписывается атомарно.

### Когда проверяется

В четырёх командах: `hot balance`, `hot send-trx`, `hot send-usdt`,
`hot activate`. Логика: если массив `networks` **непустой** и
текущий `--network` в нём **отсутствует**, программа выводит
предупреждение в `stderr`:

```
Warning: wallet "myhot" was previously used on network(s): mainnet
The current operation uses network "shasta", which is not in that list.
This wallet has already been used in operations on the listed network(s).
```

Дальше:

- если задан `--force` — продолжает без вопросов;
- если STDIN — TTY — задаёт вопрос `Continue? [y/N]:`. Ответ
  `y`/`yes` (без учёта регистра) — продолжить, всё остальное —
  ошибка `aborted`;
- если STDIN не TTY — сразу ошибка `network mismatch: use --force to
  proceed without a terminal, or run interactively to confirm`.

### Нормализация

- Любой ввод приводится к нижнему регистру и к одному из канонических
  значений `mainnet`/`shasta`.
- Дубликаты схлопываются.
- Список сортируется (`slices.Sort`).
- Пустые/неизвестные значения отбрасываются.

Никакой явной команды для удаления записи из `networks` нет — массив
только дополняется. Если нужно «забыть» предыдущую сеть, отредактируйте
JSON вручную (поле `networks`).

## Как программа находит файл по имени

`hot balance`/`send-*`/`activate` обращаются к файлу так:

1. Берут логическое имя `--name`.
2. Применяют `safeName` (превращают в безопасное имя файла).
3. Открывают файл `<safeName>.json` через `os.OpenRoot(keystoreDir)`.
4. Парсят JSON. Если `version != 1` — ошибка.

Это значит: если вы изначально создали кошелёк с именем `My Cold`,
файл получит имя `My_Cold.json`, и обращаться к нему нужно так же
(`--name "My Cold"` — преобразование сделает программа сама,
`--name My_Cold` — тоже сработает, так как обе строки нормализуются
к одному имени файла).

## Резервное копирование и переносимость

- Файл keystore самодостаточен: достаточно скопировать `<имя>.json` на
  другую машину и положить в `~/.config/monujo/keystore/` (или указать
  через `--keystore-dir`). Парольная фраза остаётся прежней.
- Параметры scrypt одинаковы у любого файла, поэтому время
  расшифрования предсказуемо (сотни мс на современной машине).
- При смене парольной фразы прямого CLI‑механизма нет: нужно
  расшифровать ключ, экспортировать его (например, через
  `hot create --export-private-key` нельзя — это только для новых
  ключей), пересоздать через `hot import` с новой фразой и удалить
  старый файл. Будьте готовы делать это аккуратно.

## Что лежит **не** в keystore

- Парольная фраза. Программа никогда не сохраняет её на диск.
- Адреса третьих лиц (получатели). Программа не ведёт «адресной
  книги».
- Логи операций. monujo не пишет журналов, кроме обновления
  `networks`.
- Любые non‑Tron ключи (Solana/BEP — вне области видимости текущей
  версии).

## Совместимость с другими keystore

Формат monujo **не совместим** напрямую ни с keystore go‑ethereum
(тоже использует scrypt+AES, но другой формат), ни с TronLink
(собственный формат). Для миграции можно:

- из go‑ethereum: расшифровать там, получить hex‑ключ, импортировать
  через `hot import --key-hex`;
- из TronLink/мнемоник: вывести приватный ключ нужного аккаунта
  (через расширение / CLI кошелька), импортировать.

`monujo` намеренно работает только с «голыми» приватными ключами
secp256k1 — без BIP39, без HD‑деривации.
