# 09. Устранение неполадок

Ниже перечислены наиболее вероятные ошибки и предупреждения,
которые вы можете увидеть. Все сообщения — на английском (так в
исходниках); рядом — пояснение и способ обхода.

## Ошибки конфигурации

### `unknown network "..." (use mainnet or shasta)`

Передано значение `--network`, отличное от `mainnet`/`shasta` (и не
пустая строка). Проверьте регистр и опечатки.

### `unknown output format "..." (use table or json)`

Неверное значение `--output`. Допустимы только `table` и `json`.

### `provide --key-hex or set MONUJO_IMPORT_KEY with the hex private key`

Команда `hot import` без ключа. Передайте `--key-hex` или экспортируйте
переменную `MONUJO_IMPORT_KEY`.

### `private key must be 64 hex characters`

Слишком короткий или длинный ввод. Префикс `0x` допустим, символы
строго `0-9a-fA-F`. Пробелы по краям обрезаются.

### `decode private key hex: ...`

Строка содержит не‑hex символы. Перепроверьте, что копировали именно
hex‑представление.

### `invalid private key length`

После декодирования получилось не 32 байта. Бывает, если в hex‑строке
есть «лишний» символ, не нарушивший проверку длины (например, не
отделённый префикс `0x` оставил не парность).

### `refusing weak private key`

Ключ из всех нулей запрещён. Импортировать его нельзя — это явная
ошибка/инжекция.

## Ошибки парольной фразы

### `passphrases do not match`

При `hot create`/`hot import` две введённые фразы различны.
Запустите команду заново.

### `decryption failed (wrong passphrase or corrupt file)`

При попытке использовать существующий keystore (`hot balance`,
`hot send-*`, `hot activate`):

- Скорее всего, пароль введён неправильно. Регистр важен.
- Возможно, файл повреждён (проверьте `cat ~/.config/monujo/keystore/<имя>.json`
  — должен быть валидный JSON v1 или v2).
- Если пароль содержит **non-ASCII** символы (кириллица, умлауты,
  лигатуры, full-width, emoji) и кошелёк создан на предыдущей сборке
  monujo без NFKC-нормализации.
  ASCII-пароли этой проблемы не имеют.

### `address mismatch in keystore`

Очень редкий случай: расшифровка прошла, но из приватного ключа
получился адрес, отличный от записанного в `address`. Это говорит о
повреждении файла (или о ручном редактировании). Не используйте
такой keystore — пересоздайте.

### `invalid decrypted key length`

Расшифрованный буфер не равен 32 байтам. Файл повреждён.

## Ошибки сумм

### `empty amount`

Передан `--amount ""`. Укажите число.

### `negative amount not allowed`

Сумма не может начинаться с `-`. Программа отказывается принимать
отрицательные числа на парсинге.

### `invalid character in amount` / `invalid character in fraction`

Допустимы только цифры и одна точка. `1,5` (с запятой) или `1e3`
(научная нотация) не поддерживаются.

### `multiple decimal points`

Больше одной точки в числе.

### `too many fractional digits (max 6)`

И TRX, и USDT имеют 6 знаков после запятой. Например, `1.1234567`
будет отклонено, нужно `1.123456`.

### `trx amount overflows int64`

TRX в санах не должен превышать `int64`. Это космически большая сумма
(больше суммарного TRX в природе), но проверка существует.

### `amount must be positive` (только для USDT)

Для `hot send-usdt` ноль и отрицательные суммы запрещены отдельной
проверкой после парсинга.

## Ошибки адресов

### `invalid Tron address: ...`

Адрес не проходит проверку Base58Check. Распространённые причины:

- лишние пробелы или `\n`;
- скопирован адрес в другой сети (например, Ethereum 0x...);
- усечена строка (адрес ровно 34 символа).

## Ошибки сети

### `trongrid accounts: HTTP 4xx: ...` / `trongrid trc20 txs: HTTP 4xx: ...`

Узел TronGrid вернул ошибку:

- `401`/`403` — проверьте API‑ключ.
- `429` — превышен рейт‑лимит. Поставьте API‑ключ или подождите.
- `5xx` — временная проблема узла. Повторите запрос.

### `trongrid: <error>`

Узел вернул HTTP 200, но в JSON стоит `success=false` и непустое
поле `error`. Сообщение приводится дословно.

### `decode accounts: ...` / `decode trc20 txs: ...`

JSON не парсится. Возможно, узел отвечает не TronGrid‑совместимым
форматом (например, вы переопределили `--http-url` и попали не туда).

### `broadcast: <message>`

gRPC принял запрос, но узел вернул ненулевой код. Типичные сообщения:

- `OUT_OF_ENERGY` / `OUT_OF_TIME` — для USDT‑перевода не хватило
  energy/bandwidth, и оплата TRX превысила `feeLimit=100 TRX`.
  Пополните адрес TRX (или стейкните energy).
- `BANDWITH_ERROR` — нехватка bandwidth.
- `CONTRACT_VALIDATE_ERROR` — обычно: получатель некорректен,
  отправитель неактивирован, контракт USDT не найден в выбранной сети.
- `DUP_TRANSACTION_ERROR` — повтор транзакции с тем же `ref_block_hash`.
  Подождите 1–2 блока.

### `empty transaction`

`gotron-sdk` вернул нулевую транзакцию — обычно это означает, что
gRPC‑узел недоступен или вернул ошибку, которую SDK обернул как
`nil`. Проверьте `--grpc-url`/доступность узла.

### `connection refused`, `context deadline exceeded` (gRPC)

Сетевые проблемы. У `WriteClient` таймаут — 60 секунд (`gRPC`),
у `ReadClient` — 30 секунд (`HTTP`). Ослабить эти лимиты в текущей
версии нельзя.

## Ошибки подтверждения сети

### `network mismatch: use --force to proceed without a terminal, or run interactively to confirm`

В файле кошелька `networks` непуст и не содержит текущий
`--network`, при этом STDIN — не TTY (например, в CI). Решение:

- Запустить интерактивно и ответить `y`;
- Передать `--force`, осознавая, что выбрана **другая** сеть, чем
  ранее использовался кошелёк;
- Удалить устаревшую запись из `networks` (отредактировать JSON).

### `aborted`

Пользователь ответил `n` (или нажал Enter) на вопрос
`Continue? [y/N]:`. Ничего не сломалось, операция отменена.

## Ошибки keystore

### `unsupported keystore version <N>`

Файл записан в формате за пределами `{1, 2}`. Вероятнее всего, он из
другой программы/будущей версии. monujo текущего релиза умеет читать
v1 (legacy scrypt) и v2 (argon2id), v1 мигрируется в v2 при первой
успешной разблокировке.

### `keystore v1 requires kdf "scrypt", got "..."` / `keystore v2 requires kdf "argon2id", got "..."`

Обнаружена несогласованная комбинация `version` и `kdf` в файле
(например, `version: 2, kdf: "scrypt"`). Это либо вручную
отредактированный файл, либо обрыв миграции. Если у вас остался
бэкап `<имя>.scrypt.bak` — переименуйте его в `<имя>.json` и
запустите любую hot-команду: она снова произведёт миграцию.

### `note: migrated wallet "..." from scrypt to argon2id; legacy backup saved as <...>.scrypt.bak`

Информационное сообщение в stderr (не ошибка): ваш старый v1 файл
успешно мигрирован в v2. Рядом появился бэкап `<имя>.scrypt.bak`.
Его можно удалить после того, как вы один раз убедитесь в
работоспособности v2 файла (например, запустив `hot list` и
`hot balance`).

### `warning: failed to migrate wallet "..." to argon2id: ...`

Миграция не удалась (например, нет прав на запись в каталог).
Оригинальная операция при этом **завершилась успешно** — ключ был
расшифрован и использован. При следующем запуске monujo попытается
мигрировать снова.

### Ручной откат v2 → v1

Если после миграции нужно вернуться на v1 (например, старый бинарник
monujo без поддержки argon2id):

1. Удалите `<имя>.json` (это новый v2).
2. Переименуйте `<имя>.scrypt.bak` в `<имя>.json`.
3. Запустите старую сборку. Новая сборка снова мигрирует файл при
   первой разблокировке, так что не используйте одновременно обе
   версии на одном и том же каталоге.

### `empty network` (внутренняя)

Возникает в `EnsureNetworkRecorded`, если `--network` нормализуется в
пустую строку. Не должно случаться при обычном использовании.

### `broadcast ok (tx <id>) but could not update wallet networks metadata: ...`

Транзакция ушла, но обновить файл keystore не удалось (например,
права доступа поменялись). Сама операция успешна — деньги отправлены.
Файл при следующей удачной отправке снова попытается обновиться.

## Симптомы и диагностика

### «Программа долго висит»

- `--api-key` пуст и упёрлись в рейт‑лимит TronGrid? Проверьте
  с ключом.
- gRPC недоступен (фаервол/пробка/региональный блок)? Попробуйте
  `--grpc-url` иной публичный узел.
- HTTP/HTTPS не доходит? Проверьте `curl https://api.trongrid.io/v1/accounts/T...`.

### «Баланс показывает 0, хотя на скане видно средства»

- Перепутана сеть. Адрес одинаков на mainnet и Shasta, но содержимое
  разное. Проверьте `--network`.
- Аккаунт не активирован — `data: []` в ответе TronGrid. Программа
  выводит нули. Активируйте через `hot activate` (или дождитесь
  входящего перевода).
- В `watch txs` вы можете не видеть транзакции, если они не
  относятся к канонически вшитому контракту USDT. Команда не
  показывает другие TRC‑20 токены.

### «Видны другие TRC‑20 токены, но не в выводе monujo»

Это by design: `watch balance` и `watch txs` фильтруют только USDT
для выбранной сети. Нет ключа `--contract-address` в текущей
версии.

### «`hot list` пустой, хотя файлы есть»

Проверьте:

- `--keystore-dir` указывает на правильный каталог;
- файлы имеют расширение `.json` (бэкапы `.scrypt.bak` в выдаче не
  участвуют — это ожидаемо);
- `version` внутри JSON равен `1` или `2`;
- поле `address` непустое;
- права доступа не «срывают» чтение от вашего пользователя.

Файлы, не прошедшие проверки, тихо пропускаются.

### «`--version` показывает `dev (unknown)`»

Бинарник собран без `-ldflags` (например, через `go build` без
Makefile). Сборка через `make build` подставит реальные значения из
`git describe`/`git rev-parse`.

## Когда сообщить о баге

Если вы наблюдаете:

- panic из стандартной библиотеки или сторонних пакетов;
- разрушение/перезапись чужого кошелька (в `safeName` или
  `EnsureNetworkRecorded`);
- неуспешную расшифровку файла, который точно использовался ранее
  с тем же паролем;
- ошибочное предупреждение о «несовпадении сети», когда сеть
  совпадает,

— приложите к багрепорту:

1. Версию: `monujo --version`;
2. Полную команду без чувствительных данных;
3. Сообщение об ошибке;
4. Анонимизированный JSON keystore (без `data_hex`, `nonce_hex`,
   `salt_hex` — оставьте `version`, `kdf`, `n/r/p` или
   `argon2_*`, `address`, `networks`).

И обязательно укажите ОС и версию Go, на которой собрано (`go version`).
