# 01. Обзор и архитектура

## Что такое monujo

`monujo` — это инструмент командной строки на Go, ориентированный на
работу с блокчейном **TRON** и токеном **USDT (TRC‑20)**. Он решает две
независимые задачи:

1. **Watch‑only** — получение публичной информации (баланс TRX/USDT,
   история переводов TRC‑20) для произвольного адреса. Ключи не нужны,
   адрес может принадлежать кому угодно (в том числе холодному
   хранилищу). Используется только публичный HTTP API TronGrid.
2. **Горячий кошелёк (hot)** — локальный зашифрованный keystore, в
   котором хранится один или несколько секретных ключей secp256k1.
   Программа умеет создавать новые ключи, импортировать существующие,
   подписывать в процессе и рассылать транзакции через **gRPC** к
   полному узлу Tron.

Solana и BEP в этой версии не поддерживаются. Внутренний макет пакета
`internal/transfer` оставлен под будущий «офлайн‑подписант», но в
текущей версии он не используется командной строкой.

## Поддерживаемые операции

- Чтение баланса TRX и USDT по любому адресу.
- Чтение истории переводов USDT (TRC‑20) — последние N транзакций.
- Создание нового кошелька (генерация случайного secp256k1 ключа).
- Импорт существующего ключа (64 hex‑символа).
- Список локальных кошельков с метаданными.
- Активация нового адреса (отправка TRX, чтобы аккаунт появился в
  реестре on‑chain).
- Отправка нативного TRX.
- Отправка USDT (TRC‑20) — на mainnet используется канонический контракт
  Tether, на Shasta — тестовый токен с похожей семантикой.

## Архитектура

Кодовая база разбита на несколько внутренних пакетов:

```
cmd/monujo/main.go            # точка входа, прокидывает версию из ldflags
internal/cli/                 # парсинг команд и флагов (cobra)
  root.go                     # глобальные флаги и Execute()
  watch.go                    # подкоманды watch
  hot.go                      # подкоманды hot
  network_confirm.go          # интерактивное подтверждение --network
internal/config/config.go     # типы Network, OutputFormat и Config
internal/app/                 # связывает CLI с доменом
  watch_service.go            # форматирует watch‑вывод (table/json)
  hot_service.go              # выполняет горячие операции
internal/keystore/            # шифрование/дешифрование, метаданные
  keystore.go                 # формат файла v1, scrypt + AES‑GCM
  passphrase.go               # ввод пароля без эха
internal/domain/              # неизменяемые типы данных, парсинг сумм
  asset.go                    # ParseTRXDecimal, ParseUSDTDecimal, форматтеры
  transfer.go                 # TRC20TransferRow
internal/tron/                # сетевые клиенты
  read_client.go              # HTTP к TronGrid (account, trc20 history)
  write_client.go             # gRPC к полному узлу + подписание
  address.go                  # ValidateBase58Address
  constants.go                # адреса USDT‑контрактов
internal/transfer/envelope.go # JSON‑конверты для будущего офлайн‑подписания
```

### Поток выполнения

#### Команда `watch ...`

1. `cmd/monujo/main.go` вызывает `cli.Execute()`.
2. `cli.newRootCmd()` регистрирует глобальные флаги и подкоманды,
   парсит аргументы.
3. `cli.loadConfig()` собирает структуру `config.Config` из флагов и
   переменных окружения.
4. `app.NewWatchService(cfg)` создаёт `tron.ReadClient`.
5. `WatchService.PrintBalance()` или `PrintTransfers()` выполняет
   HTTP‑запросы к TronGrid и печатает результат в нужном формате
   (`table` или `json`).

#### Команда `hot ...`

1. То же `Execute()` → `loadConfig()`.
2. Для команд, работающих с уже существующим ключом
   (`balance`/`activate`/`send-trx`/`send-usdt`) сначала вызывается
   `confirmWalletNetworkForOperation()`: считываются метаданные
   `networks` из файла кошелька и при несовпадении с `--network`
   запрашивается подтверждение в интерактивном режиме (или ошибка, если
   нет TTY и не передан `--force`).
3. Запрашивается парольная фраза (без эха, через `golang.org/x/term`).
4. `app.NewHotService(cfg).<Op>()`:
   - `keystore.LoadPrivateKey()` расшифровывает keystore
     (scrypt → AES‑GCM), сверяет адрес.
   - Для отправок строится транзакция через `tron.WriteClient`
     (`gotron-sdk`), подписывается локально и рассылается через gRPC.
   - При успешной отправке вызывается
     `keystore.EnsureNetworkRecorded()`, чтобы текущая сеть появилась в
     метаданных файла, если её там не было.
5. Печатается результат (`table` или `json`).

### Где живут данные

- **Конфигурация**: только в окружении и аргументах. На диске
  никаких yaml/json‑конфигов программа не создаёт.
- **Зашифрованные ключи**: каталог `~/.config/monujo/keystore/` по
  умолчанию, переопределяется через `--keystore-dir` или
  `MONUJO_KEYSTORE_DIR`. Один ключ — один файл вида
  `<имя>.json` с правами `0600`.
- **Логи**: их нет. Программа печатает результат в `stdout`,
  диагностику и предупреждения — в `stderr`. В файлы ничего не
  записывается, кроме keystore.

## Модель угроз

`monujo` — это **программный** кошелёк, не аппаратный. Он защищает
ключ от утечек на уровне файловой системы (шифрование AES‑256‑GCM с
ключом, выведенным через scrypt из парольной фразы), но **не
противостоит** компрометации самой машины: процесс держит расшифрованный
ключ в памяти на время отправки, экран и буфер обмена контролирует ОС.

Допущения, при которых система остаётся безопасной:

- Бинарник собран из доверенных исходников (вы сами или ваш CI).
- Машина не скомпрометирована (нет кейлоггеров, чужого root‑доступа,
  свопа, читаемого посторонними).
- Файлы keystore лежат с правами `0600`, домашний каталог защищён.
- Парольная фраза достаточно стойкая, не сохраняется в истории
  shell.
- API‑ключ TronGrid (если используется) не уходит в публичные
  репозитории.

Программа активно сопротивляется типичным ошибкам:

- Стирает (zero‑fill) парольные фразы и буферы с приватным ключом
  сразу после использования.
- Не использует `float64` для сумм (TRX и USDT считаются как `int64`
  или `*big.Int`), чтобы исключить ошибки округления.
- Чтение файлов keystore идёт через `os.Root`, чтобы исключить
  прыжки через симлинки за пределы каталога keystore.
- Имя файла санитизируется: разрешены только `[a-zA-Z0-9_-]`,
  остальные символы заменяются на `_`. Пустое имя превращается в
  `default`.
- Атомарная запись метаданных (через временный файл + `rename`)
  при дописывании сети в keystore.

## Что НЕ делает monujo

- Не управляет аппаратными подписантами.
- Не делает офлайн‑подписание (заготовка есть в
  `internal/transfer`, но команды CLI отсутствуют).
- Не работает с TRC‑10, NFT, контрактами кроме явно вшитого USDT.
- Не делает мульти‑подпись.
- Не показывает баланс других TRC‑20 токенов.
- Не делает обмен/конвертацию.
- Не отправляет уведомления, не следит за сетью в реальном времени,
  не имеет демона.

Это сознательно минимальный CLI «однократного действия»: вызвал —
получил результат — вышел.
