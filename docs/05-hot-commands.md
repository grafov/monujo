# 05. Команды `hot`

Группа `hot` объединяет **онлайн-операции** с уже существующим
кошельком из локального keystore: проверка баланса, отправка TRX и USDT.
Все команды этой группы делают
сетевые вызовы (HTTP к TronGrid и/или gRPC к полному узлу).

> Lifecycle keystore-файла (создание, импорт, список) живёт в
> отдельной группе [`monujo wallet`](11-wallet-commands.md) и сетевых
> вызовов не делает; те же файлы потом используются и `hot`, и
> `offline sign`.

```text
monujo hot
├── balance       — баланс TRX и USDT по имени кошелька или адресу (без пароля)
├── send-trx      — отправить TRX
└── send-usdt     — отправить USDT (TRC-20)
```

Глобальные ключи (`--network`, `--output`, `--api-key`,
`--keystore-dir`, `--http-url`, `--grpc-url`) применимы ко всем
подкомандам. Подробнее см. [03 — Конфигурация](03-configuration.md).

## Общие принципы

- **`--addr` и `--from` / `--to`**. Для `hot balance` субъект запроса
  задаётся флагом **`--addr`**: имя файла в keystore (без `.json`) или
  Tron base58 адрес. Для `hot send-trx` и `hot send-usdt` отправитель —
  **`--from`**, получатель — **`--to`**. Значение — либо имя в keystore,
  либо base58 адрес (T..., 34 символа). Распознавание автоматическое:
  всё, что проходит валидацию base58, считается адресом, иначе — именем;
  резолв через `keystore.ListWallets` без расшифровки.
    - **`--addr` в `hot balance`** допускает произвольный адрес: команда
      читает балансы с сети и keystore не требуется.
    - **`--from` в `hot send-trx`/`hot send-usdt`** принимает адрес только
      если он совпадает с `address` одного из локальных кошельков
      (нужен приватный ключ). Иначе — ошибка и предложение передать имя.
    - **`--to`** принимает любой валидный base58-адрес или имя локального
      кошелька (резолв в адрес).
- **Ввод парольной фразы**. Команды, которым нужна подпись
  (`send-trx`, `send-usdt`), запрашивают парольную фразу
  через TTY без эха. `hot balance` пароль **не запрашивает**: адрес
  он читает из открытых метаданных файла.
- **Стирание секретов**. Парольная фраза и материал приватного ключа
  затираются нулями (`ZeroPassphrase`, `Wipe`) сразу после
  использования.
- **Подтверждение сети**. Если файл кошелька уже содержит
  непустой список `networks` и текущий `--network` в нём
  отсутствует, перед выполнением операции выводится предупреждение и
  запрашивается подтверждение `[y/N]`. Чтобы пропустить это
  подтверждение в скриптах — `--force`. Без TTY и без `--force`
  возвращается ошибка `network mismatch: use --force to proceed
  without a terminal, or run interactively to confirm`.
- **Запись метаданных**. После успешной отправки TRX или USDT
  программа дописывает текущий `--network` в массив `networks`
  файла кошелька (без перешифрования; меняются только метаданные,
  атомарной заменой через `rename`).

## `hot balance`

Показывает баланс TRX и USDT для **именованного** локального
кошелька. Адрес берётся из открытых метаданных файла keystore (то же
поле, что показывает `wallet list`), поэтому **парольная фраза не
запрашивается** — это read-only операция.

### Использование

```bash
monujo hot balance --addr <ИМЯ>
monujo --network shasta hot balance --addr testhot --force
```

### Флаги

| Флаг      | Тип    | Обязательный | По умолчанию | Описание                                                                                        |
|-----------|--------|--------------|--------------|-------------------------------------------------------------------------------------------------|
| `--addr`  | string | да           | —            | Имя кошелька в keystore ИЛИ Tron base58 адрес (произвольный).                                   |
| `--force` | bool   | нет          | `false`      | Пропустить интерактивное подтверждение, если текущий `--network` не записан в `networks` файла. |

### Что происходит

1. Проверка `networks` файла → возможное подтверждение.
2. `keystore.ListWallets()` находит запись по `--addr`, берёт её
   `address` из открытых метаданных.
3. Тот же HTTP‑запрос, что в `watch balance`, и тот же формат
   вывода (`table`/`json`).

> Расшифровка ключа при `hot balance` больше **не выполняется**.
> Это значит, что эта команда не подтверждает целостность
> зашифрованного содержимого; впрочем, любая последующая
> подписывающая операция (`hot send-*`, `offline sign`) сделает это
> через `keystore.LoadPrivateKey()` и упадёт, если файл повреждён.

### Пример

```text
$ monujo hot balance --addr myhot
Address: TLcVUPa...
TRX:     50.123456 (50123456 sun)
USDT:    100 (minimal units 100000000)
```

В JSON структура такая же, как у `watch balance` (см. [04](04-watch-commands.md#пример-формат-json)).

## `hot send-trx`

Отправляет нативный TRX с локального кошелька на любой адрес.
Первый входящий TRX на новый адрес в Tron делает аккаунт видимым для
read API — для этого достаточно обычного `send-trx` с небольшой суммой
на целевой адрес (или крана на Shasta).

### Использование

```bash
monujo hot send-trx --from <ИМЯ> --to <ADDR> --amount <TRX>
```

### Флаги

| Флаг       | Тип    | Обязательный | По умолчанию | Описание                                     |
|------------|--------|--------------|--------------|----------------------------------------------|
| `--from`   | string | да           | —            | Имя кошелька‑источника ИЛИ его base58‑адрес (должен соответствовать локальному keystore‑файлу). |
| `--to`     | string | да           | —            | Получатель: base58‑адрес ИЛИ имя локального кошелька.                                           |
| `--amount` | string | да           | —            | Сумма TRX (десятичное число, до 6 знаков).   |
| `--force`  | bool   | нет          | `false`      | Пропустить интерактивное подтверждение сети. |

### Что происходит

1. Подтверждение сети (см. общие принципы выше).
2. Запрос пароля.
3. Парсинг суммы: `domain.ParseTRXDecimal`. Допускается до 6 знаков
   после точки. Отрицательные числа, пустая строка, лишние символы
   и переполнение `int64` приводят к ошибке.
4. Валидация адреса получателя.
5. Расшифровка keystore.
6. Подключение по gRPC, построение транзакции
   (`gotron-sdk` `Transfer`), подписание ECDSA, рассылка
   (`Broadcast`).
7. Если broadcast вернул не‑нулевой код — ошибка `broadcast: <message>`.
8. Дозапись `--network` в метаданные.

### Пример: формат `table`

```text
$ monujo hot send-trx --from myhot --to TXYZ... --amount 12.5
Passphrase: ********
Broadcast OK
Network: mainnet
TxID:    abc123...
From:    TLcVUPa...
To:      TXYZ...
TRX: 12.5
```

### Пример: формат `json`

```json
{
  "tx_id": "abc123...",
  "from": "TLcVUPa...",
  "to": "TXYZ...",
  "kind": "TRX",
  "amount": "12.5",
  "network": "mainnet"
}
```

### Особенности

- Идентификатор транзакции вычисляется локально как
  `sha256(proto.Marshal(tx.GetRawData()))` — Tron использует именно
  этот хеш как `txID`. Поэтому `tx_id` доступен сразу после успешной
  рассылки, даже до её попадания в блок.
- Tron берёт оплату либо за счёт **bandwidth** (бесплатно, в пределах
  суточного лимита), либо «сжигая» TRX, если bandwidth исчерпан.
  monujo не запрашивает явной оценки fee; для нативных переводов это
  обычно безопасно. Если у адреса нет TRX вообще, broadcast
  завершится ошибкой.
- При успехе текущий `--network` будет добавлен в метаданные файла
  (если ещё не записан). Если файл по какой‑то причине не удалось
  обновить, программа всё равно сообщит об успешном broadcast и
  выведет ошибку метаданных:

  ```
  broadcast ok (tx <id>) but could not update wallet networks metadata: <причина>
  ```

## `hot send-usdt`

Отправляет USDT (TRC‑20) с локального кошелька на любой адрес.
Используется контракт, выбранный по `--network`:

- mainnet: `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t` (Tether),
- Shasta: `TG3XXyExBkPp9nzdajDZsozEu4BkaSJozs` (тестовый токен,
  **не настоящий** USDT).

### Использование

```bash
monujo hot send-usdt --from <ИМЯ> --to <ADDR> --amount <USDT>
```

### Флаги

| Флаг       | Тип    | Обязательный | По умолчанию | Описание                                                               |
|------------|--------|--------------|--------------|------------------------------------------------------------------------|
| `--from`   | string | да           | —            | Имя кошелька‑источника ИЛИ его base58‑адрес (должен соответствовать локальному keystore‑файлу). |
| `--to`     | string | да           | —            | Получатель: base58‑адрес ИЛИ имя локального кошелька.                                           |
| `--amount` | string | да           | —            | Сумма USDT (десятичное число, до 6 знаков). Должна быть положительной. |
| `--force`  | bool   | нет          | `false`      | Пропустить интерактивное подтверждение сети.                           |

### Что происходит

1. Подтверждение сети.
2. Запрос пароля.
3. Парсинг суммы: `domain.ParseUSDTDecimal` → `*big.Int` минимальных
   единиц. До 6 знаков после точки. Сумма должна быть строго
   положительной (`amount must be positive` иначе).
4. Валидация адреса получателя.
5. Расшифровка keystore.
6. gRPC: `TRC20Send(from, to, contract, amount, feeLimit=100_000_000 sun)` —
   формирует contract call USDT `transfer(address,uint256)`.
7. Подписание ECDSA, broadcast.
8. Дозапись `--network` в метаданные.

### Пример: формат `table`

```text
$ monujo hot send-usdt --from myhot --to TXYZ... --amount 10.25
Passphrase: ********
Broadcast OK
Network: mainnet
TxID:    def456...
From:    TLcVUPa...
To:      TXYZ...
USDT: 10.25 USDT
```

### Пример: формат `json`

```json
{
  "tx_id": "def456...",
  "from": "TLcVUPa...",
  "to": "TXYZ...",
  "kind": "USDT",
  "amount": "10.25 USDT",
  "network": "mainnet"
}
```

### Особенности

- TRC‑20 переводы тратят **energy**. Если у адреса не хватает
  стейкнутой `energy`, недостающее количество компенсируется
  сжиганием TRX, но не более `feeLimit = 100 TRX`. Если ваш баланс
  TRX меньше нужного, broadcast завершится ошибкой `OUT_OF_ENERGY`
  или `OUT_OF_TIME` от узла.
- Лимит комиссии (`100 TRX`) вшит в код (`config.defaultFeeLimitSun`).
  В текущей версии его нельзя поменять флагом.
- На Shasta тестовый USDT‑контракт может отличаться по поведению от
  настоящего Tether (decimals, события, методы — программа исходит
  из стандарта `transfer(address,uint256)` и 6 знаков). Перед
  использованием на Shasta убедитесь, что это именно тот контракт,
  для которого валиден этот вызов.
